## Modifications

This repository reorganizes and adapts the original dataset for use as an Agent Skill, including:

- creating `SKILL.md` as the Agent instruction entry point;
- organizing university information into local reference files;
- adding an index for school lookup;
- adding `references/aliases.md`, an alias / abbreviation / former-name lookup index (2,827 unique entries covering 2,348 schools plus an "ambiguous nicknames" table), generated by `tools/build_aliases.py`; nicknames that genuinely point at several schools (`地大`, `华师`, `华农`, `中国地质大学`, `中国石油大学`) are listed there instead of the unique-alias table, and `tools/query.py` refuses to guess when it sees one;
- adding `tools/query.py`, a structured query and reverse-filter tool that classifies each answer within a question block instead of relying on literal `grep` matches, plus a `--selftest` regression suite for the classifier;
- **rewriting the polarity classifier** into `tools/polarity.py`: the previous version used one question-agnostic keyword lexicon, which misclassified negation ("不断电" read as an affirmation of "断电" ), affirm-vs-negate pairs ("不贵" read as "贵"; "是上下铺" read as "是"), and quality questions. The new classifier keeps a per-question `Spec` (exclusive nouns + generic phrasing + campus/hedge markers) and strips negated spans before testing affirmative ones. A wrong answer is now biased towards `unknown` rather than a confident mistake. The classifier also prints its decision rule (`yes = …`, `no = …`) with every result;
- adding `tests/` (unittest, also collectible by pytest) with per-question regression cases drawn from the dataset, parser/index/alias unit tests and a CLI smoke test, plus `.github/workflows/ci.yml` (unit tests on Python 3.10–3.13, a pytest run, and a data-integrity job) and `tools/check_all.sh` for local one-shot verification;
- adding `tools/verify.py`, a data-integrity regression check;
- adding `tools/consolidate.py`, which merges misplaced upstream entries (where a respondent typed an explanatory sentence into the school-name field) back into the correct school file;
- adding `tools/patch_index.py`, which applies this repository's index corrections (date, upstream SHA, school / province counts, annotation of unresolvable upstream abbreviations) idempotently;
- **removing alias-table collisions**: the alias generator previously derived aliases by "unique substring containment", which turned 327 real school names into aliases pointing at a *different* school's file (e.g. `上海交通大学` → `上海交通大学医学院`). That rule was deleted; derived aliases that would equal another real school's full name are now discarded, and `tools/verify.py` fails if such a row reappears;
- **redacting personal information** (see Privacy below);
- **fixing the reverse filter's aggregation and labels**: a keyword that matches several questions (e.g. `宿舍` → 7 questions) used to emit one row per (school, question) and report the row count as the number of schools (15,176 rows for 3,424 schools). Rows are now merged per school with a `命中维度` (matched-question count) column, the reported count is unique schools, and `--polarity mixed` prints `分化 / 分校区差异` instead of reusing the `no` label;
- **parsing the free-form supplement**: entries there use a bare `A12345: …` prefix (no `- `), which the parser previously ignored, so `--q all` reported the free-form section as having 0 answers across the 3,206 affected files. The parser now accepts both prefixes; the free-form section carries no polarity verdict;
- minor cleanups: removed a stray leading period from one school name in the index and in its file heading, and annotated three upstream identifiers (`tj`, `xn`, `swpu`) that could not be resolved to a real school name.

Data last refreshed from upstream on 2026-09-19 (generated branch `0abf14dfc897`, commit date 2026-09-19). Compared file by file against that commit, the archived library (2,705 files) is byte-identical apart from the redaction below; in the active library the only content differences are (a) the leading-period fix noted above, (b) the merge of one misplaced entry (respondent `A33177`, 2026-02, 25 answers + 1 free-form supplement) into 广东轻工职业技术大学, and (c) the privacy redaction below. Includes both active data (3,448 schools, responses from 2023-2026) and archived data (2,705 schools, responses from 2021-2022, i.e. submitted before 2023-01-01).

## Privacy

The upstream generated data preserved identifiers that questionnaire respondents voluntarily provided, in two places:

1. the "数据来源" (`<li>`) list at the top of each school file — mostly personal e-mail addresses (2,672 in the active library, 1,965 in the archived library);
2. the answer bodies and the free-form supplement section — students frequently leave an e-mail address, mobile number, QQ number, WeChat ID or Telegram link so that others can contact them, occasionally even base64-encoded (one entry uses a triple-base64-encoded e-mail address).

Because this repository is published publicly under CC BY-NC-SA 4.0, both kinds are replaced:

- source-list identifiers become stable pseudonyms (`实名反馈者 N`); the same original identifier always maps to the same number, and new numbers continue from the current maximum so that an incremental sync never reuses an existing number. Questionnaire IDs (`A12345`) and submission timestamps are unchanged, so a response can still be attributed to a single (pseudonymous) source and traced back to the upstream questionnaire ID;
- contact details inside answer bodies become readable placeholders (`[邮箱已脱敏]`, `[手机号已脱敏]`, `[QQ已脱敏]`, `[微信已脱敏]`, `[Telegram已脱敏]`, `[社交账号已脱敏]`); a base64 fragment that decodes to such information is replaced wholesale with `[已脱敏的编码内容]`.

`tools/redact.py` performs all of this idempotently; `python3 tools/redact.py --check` reports anything still unredacted and exits non-zero.

- The mapping from original identifier to pseudonym is not published in this repository; the redaction is deterministic and reproducible through `tools/redact.py` for maintainers who need to re-run it after an upstream sync.
- No answer bodies were otherwise altered: question headings, questionnaire IDs, timestamps and all non-contact text are unchanged.

If you are the author of an upstream questionnaire response and want your entry removed entirely rather than pseudonymized, please open an issue.
